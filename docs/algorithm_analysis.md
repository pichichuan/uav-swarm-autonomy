# 多无人机协同算法解析

## 1. 系统闭环

每个仿真周期都执行同一条数据链：

```text
MuJoCo 真值 / 传感器观测
        ↓
语义障碍物（静态通信塔、动态行人）
        ↓
局部占据地图 + 多机状态共享
        ↓
任务目标选择、动态预测、机间解冲突
        ↓
期望速度 / 高度参考 → PD 外力控制 → MuJoCo mj_step
```

核心代码位于 `src/swarm_autonomy/`；`mujoco_demo.py` 是真实刚体仿真入口，`tools/render_mujoco_demo.py` 生成仓库中的动画。

## 2. 障碍物识别与地图

场景包含两类可区分的语义障碍：深灰色通信塔是固定障碍，蓝色行人是动态障碍。感知层将观测写为 `SemanticObservation`，每架无人机把它投影到自身的 `OccupancyMap`；地图增量随后可通过 DDS/Zenoh 发送给同伴并合并。

轻量实现的目的，是把数据契约和可测试行为保留在不依赖 ROS 的代码中。接入真机时，用 YOLO 加深度或 LiDAR 关联替换观测来源，用 KISS-ICP/VINS-Fusion 替换位姿来源即可。

## 3. 动态避障

行人的下一时刻位置按恒速模型估计：

```text
p_pred = p_person + 1.2 × v_person
```

当预测距离小于安全半径时，无人机的速度参考叠加远离预测点的回避向量；随后进行限速。控制器并不改写无人机坐标，而是只施加力，MuJoCo 负责积分、重力、接触与碰撞判定。

## 4. 多机协同如何发生

协同不是两架机沿两条预设路径各自飞行。动态风险被任一架无人机检测到后，会产生一条共享的 `conflict` 状态：

```text
发现动态冲突的无人机
   └─ 广播 conflict / 当前状态
         └─ 同伴把高度目标增加 0.55 m
               └─ 两机从不同航层通过，再回归各自任务高度
```

同时，每架无人机持续计算与同伴的间距；过近时在速度参考中加入排斥项。因此协同包含两层：事件型的航层解冲突，以及连续型的机间最小间距约束。

在 GIF 中，顶部状态从 `COORDINATED FLIGHT` 切换到 `PEER ALTITUDE DECONFLICTION` 的片段，就是共享冲突状态触发同伴升层的时刻。

## 5. 可验证指标

`tests/test_mujoco_demo.py` 会验证任务成功、动态障碍零碰撞、至少一次动态预测介入和至少一次多机协同事件。当前演示配置的渲染结果为：18 秒任务、0 次动态碰撞、271 次动态风险介入、2 次航层解冲突。

## 6. 上真机替换点

| 当前演示模块 | 真机/高保真替换模块 |
|---|---|
| MuJoCo 真值状态 | PX4 local odometry + VINS-Fusion / KISS-ICP |
| 语义障碍物对象 | YOLO + 深度相机或 LiDAR 3D 关联 |
| 局部占据栅格 | Fast-Planner ESDF / 局部地图 |
| 速度回避与高度解冲突 | EGO-Planner-v2 多机轨迹优化 |
| 进程内共享状态 | ROS 2 DDS / Zenoh 跨机状态与地图增量 |

PX4 的 geofence、failsafe、遥控接管和飞控侧碰撞保护必须保留；本仓库的规划器只能作为上层自主逻辑。
